# 肺智瞳多模态肺部异常智能辅助筛查系统

参赛技术文档

版本日期 2026年11月7日

## 摘要

本项目面向基层医疗辅助筛查与医学人工智能教学场景，将胸部X光影像、自然语言主诉和结构化问诊信息组织为可追踪的筛查流程。系统以EfficientNetV2-S完成基础胸片三分类，结合症状规则、四条医学知识摘要的TF-IDF检索、按方向专病复核、DeepSeek可选整合与一致性保护，输出风险方向、主要依据和后续检查建议。React与TypeScript提供Web交互，FastAPI衔接原Python能力，LangGraph负责状态传递、条件分支与有限反馈。

项目的技术重点是多源证据组织、按需复核、过程解释和失败回退。本次已完成六个演示样例及无影像路径的流程一致性检查、11项仓库测试、一次虚构输入的DeepSeek实测和七类异常回退验证。六个精选样例不能代表独立临床评测；当前不据此宣称准确率提升、漏诊率降低或临床有效性。

本技术文档由原项目研究报告改编，更新了前端、仓库结构和可验证实验结果，保留原项目的分层筛查与证据协同思路。系统定位为可运行的演示及辅助筛查原型，不替代医生最终诊断。

# 1 项目概述

## 1.1 背景与问题

原项目围绕基层医院、乡镇卫生院和公共卫生初筛等潜在场景展开，关注胸片判读资源有限、患者症状描述不规范、单一影像模型输出依据不透明等问题。胸片能够提供肺部异常的影像线索，但项目不把单张胸片、单个症状或一个模型分数当作确诊依据。WHO有关胸片筛查的资料也区分分诊、筛查与诊断辅助等用途。[1][2]

对一个辅助筛查Web原型而言，关键任务不只是显示影像标签，还包括规范输入、保留证据、呈现复核路径，以及在证据不足时提示进一步检查。原研究报告提出的“多源证据协同分诊”是本项目继续沿用的设计主线。

## 1.2 项目目标

系统以胸部X光影像和问诊信息为输入，通过基础影像分诊、症状解析、知识召回、风险路由、专病方向复核、综合判断和一致性审查，形成辅助筛查结果。结果覆盖正常或低风险、感染性异常倾向、结核或慢性异常风险倾向、需进一步检查等状态。

系统同时展示模型分数、召回知识、路由原因、复核意见和执行轨迹，使操作者能够查看输入到输出之间的关系。面向竞赛与教学，项目还提供无云端密钥可运行的本地流程、清晰的代码目录及可重复执行的检查入口。

## 1.3 当前交付范围

已交付React前端、FastAPI本地接口、原LangGraph工作流、两套本地三分类权重、六个演示样例和环境配置。默认使用EfficientNetV2-S；DenseNet121为可选替代模型，并非双模型投票。肺炎与结核专病模型保留在线或缓存加载路径，未包含其权重；未成功加载时使用明确标识的规则复核。

项目尚未提供生产级用户认证、病例长期存储、DICOM工作站集成或多中心临床验证。基层部署、公共卫生使用和商业价值属于后续需验证的应用方向，不能由当前功能演示直接推导。

# 2 需求分析

## 2.1 用户与典型任务

原研究报告将基层医生作为潜在辅助使用者。当前原型首先服务于演示操作者、评审和医学AI教学：操作者希望快速填写问诊、上传样例并理解证据；评审需要从仓库独立启动程序、区分真实模型与回退模块；教学使用者需要观察条件分支和反馈过程。

典型任务由“规范录入—影像初筛—证据召回—方向复核—解释输出”组成。既保留症状原文，又通过病程、发热、咳痰和慢性信号等选项减少输入遗漏。输出应包含风险方向和下一步检查提示，不只给出一个分类标签。

## 2.2 功能需求

| 编号 | 需求 | 当前实现与验收方式 |
| --- | --- | --- |
| F1 | 规范病例输入 | 六组问诊选项 自定义病程和痰液 自由文本补充 |
| F2 | 处理影像与缺失影像 | PNG/JPEG上传 保留无图像路径 非图像拒绝 |

## 2.3 非功能需求与边界

可复现要求落实为依赖清单、环境变量模板、模型哈希、启动检查和测试入口。可维护性通过前后端分离、职责明确的节点及统一代码格式实现。交互需求包括等待状态、输入校验、四个结果标签和窄屏适配。

隐私方面只应使用脱敏且已授权的数据。图像在本地推理；启用云端LLM时会发送症状、派生分数与知识证据，页面告知这一范围。临时图像在处理完成或异常后删除，进程被强制终止仍可能遗留文件。上述措施不等于已完成生产安全或合规认证。

# 3 系统架构设计

## 3.3 状态驱动与多节点流程

原项目将影像路径、症状文本、症状特征、模型分数、召回知识、路由结果和结论统一写入MedicalState。各节点读取已有证据并补充状态，而不是各自独立输出互不关联的结果。LangGraph以节点和条件边表达这一过程。[3]

| 节点 | 输入和主要职责 |
| --- | --- |
| SymptomAgent | 从问诊文本抽取病程 关键词与否定语境 |
| ImageAgent | 调用主CNN 形成三分类及风险分数 |
| KnowledgeAgent | 查询本地摘要 记录召回与路由证据 |
| RouteAgent | 根据影像 症状与知识证据选择分支 |
| InfectiousSpecialist | 感染方向的可选模型或规则复核 |
| ChronicSpecialist | 慢性方向的可选模型或规则复核 |
| DiagnosisAgent | 可选LLM或本地规则整合证据 |
| ReviewAgent | 检查方向矛盾并实施一致性保护 |
| CheckAgent | 形成下一步检查及复核建议 |
| SelfFeedbackAgent | 在满足条件时补充保守规则并返回整合 |

## 3.4 路径与反馈约束

症状、影像和知识节点之后进入路由，可直接综合判断，或进入感染、慢性及联合复核路径。慢性复核之后可继续感染复核；完成综合判断、审查和检查建议后，按继续条件决定结束或反馈。本次边界与冲突演示中出现最多三轮反馈记录。

这里的Agent主要是规则驱动的职责节点，反馈由代码条件约束，不是无限自主推理。项目没有将LangGraph框架本身视为原创，也不宣称已经实现模型自主规划、MCP或Function Calling工具选择。

# 4 AI技术方案

## 4.1 选型理由与组合方式

本项目沿用原研究报告的“基础影像分诊—按方向复核—知识增强—证据整合”路线。视觉模型负责图像判别，规则负责结构化线索与保守约束，可选LLM负责证据整合表达，工作流负责可追踪的执行顺序。职责分离便于单独检查各环节。

| 技术 | 选择理由 | 集成方式与限制 |
| --- | --- | --- |
| EfficientNetV2-S | 复用已有胸片三分类权重 支持本地运行 | timm构建并加载state_dict 默认主模型 |
| DenseNet121 | 提供已有替代结构供对比与核验 | 显式切换权重和架构 不与主模型投票 |
| 专病ViT模型路径 | 按风险方向组织二次评估 | 权重未随包交付 无缓存时规则回退 |
| TF-IDF检索 | 四条摘要可轻量离线检索 依赖少 | 余弦相似度取top-3 不等同向量数据库 |
| LangGraph | 条件分支与共享状态直接可表达 | 记录节点轨迹和有限反馈 |
| DeepSeek兼容API | 将已有证据转为结构化说明 | 可选联网能力 失败保留本地整合 |

EfficientNetV2原论文讨论了网络结构与训练效率的设计，但论文结果不直接代表本项目胸片表现。[4] 本项目采用已有可运行权重的工程选择，不宣称通过本次工作重新完成了网络结构发明或独立训练。

## 4.2 方案取舍

本地CNN降低了基础演示对云端的依赖；小型检索索引便于解释召回来源；按方向复核避免每个输入都执行全部专病分支。代价是症状理解和检索目前较轻量，在线专病模型未验证，知识覆盖范围有限。选型理由是当前原型的可运行性与证据可检查性，不是已证明在所有数据上优于其他方案。

# 4 AI技术方案

## 4.3 影像模型与预处理集成

ImageAgent将胸片转为RGB，缩放至512×512，转换为张量并归一化。timm根据架构名称创建三分类网络，加载本地state_dict并设为推理模式；softmax生成normal、pneumonia、tuberculosis三类分数，随后映射为页面展示的风险方向。

原项目的基础模型在整个流程中承担第一道影像分流。影像高风险可触发方向复核；图像缺失或模型失败必须保留相应来源标记，不将启发式回退描述为CNN推理。

| 核验项目 | 当前记录 |
| --- | --- |
| 类别顺序 | normal pneumonia tuberculosis |
| 主模型输入 | RGB 512×512 |
| 归一化均值 | 0.485 0.456 0.406 |
| 归一化标准差 | 0.229 0.224 0.225 |
| EfficientNet内嵌训练配置 | AdamW 学习率0.0003 batch_size为16 |
| 目标训练轮次与checkpoint | 配置epochs为30 checkpoint字段epoch为4 |
| DenseNet checkpoint | 包含epoch为30及模型与优化器状态 |

EfficientNet权重内嵌config中的类别、尺寸和归一化与当前代码一致。checkpoint编号与目标训练轮次不能替代完整训练日志；两套权重的作者和训练数据授权仍需补证，DenseNet的完整训练预处理依据也未取得。

## 4.4 已实现的推理优化

模型使用进程内缓存，避免同一权重在每次请求中重复初始化；推理阶段不计算梯度。主CNN之后通过条件路由按需执行专病复核。当前未执行稳定并发压测或硬件性能基准，因此不填写吞吐量、加速倍数或响应时间保证。

# 4 AI技术方案

## 4.5 知识检索与证据前移

KnowledgeAgent围绕症状文本、症状特征和影像风险构建查询，从四条本地摘要中召回证据。摘要标签涉及ATS/IDSA成人肺炎指南、WHO结核事实页、WHO胸片筛查资料及本地分诊摘要；已补充官方出处入口。[1][2][5]

当前TfidfVectorizer使用1至2 gram特征，计算查询与摘要的余弦相似度并取前三条。[6] 结果进入共享状态，既用于报告说明，也可形成复核路由的补充信号。这里沿用原稿“知识证据前移”的思路，但不把四条摘要描述成已完成持续更新的医学知识平台。

## 4.6 LLM集成与输出控制

DiagnosisAgent通过兼容的/chat/completions接口发送症状、特征、影像分数、专病说明及召回证据，temperature设为0，提示要求返回包含筛查方向、置信度、依据和鉴别建议的JSON。[7] 请求不包含原始图像。

程序解析结构化内容、限制置信度范围，再调用一致性保护。无密钥、HTTP错误、网络超时、连接重置或不合规内容时使用本地规则。现有解析不是完整JSON Schema校验，亦未证明输出已通过医学质量审查或置信度校准。

## 4.7 优化策略与待验证部分

已实现的优化包括索引缓存、按方向复核、限制输入证据范围、规则回退和保守反馈。前端显示模型来源、路由与执行轨迹，便于发现降级。后续应以独立标注集评测中文检索、阈值和解释质量，再考虑扩大知识库、改进分词或引入语义检索。

六图关闭文档召回的功能消融已执行，但没有改变最终类别，不能据此宣称检索提高了独立准确率。该消融也保留了症状规则与兜底知识，不能等同于删除全部RAG相关逻辑。

## 5.1 问诊与影像交互

原项目使用“结构化选项加自由文本”的录入方式，本次React迁移保留了病程、发热、咳痰、胸痛气促、盗汗消瘦咯血和痰液特点六组输入。病程及痰液支持自定义，症状原文用于补充表单未覆盖的信息。

Python端复用原build_structured_symptom函数拼接问诊文本，再由症状节点按关键词、病程和否定语境抽取特征。因此这里的症状解析主要是规则处理，不将其描述为已训练的临床语义理解模型。

# 5 核心功能实现

## 5.2 接口与图像生命周期

前端将问诊对象序列化到multipart表单的answers字段，影像作为可选image字段。FastAPI校验JSON结构、后缀、大小与真实图像格式；有效影像写入唯一临时文件后传给原工作流。成功和异常路径均通过finally删除本次临时文件，并关闭上传流。

API层用锁保护核心代码共享的模型缓存和LLM错误状态。它是当前原型的串行保护方式，不等于完成了多用户高并发部署设计。接口异常返回简明提示，不把内部服务错误当作筛查结论。

## 5.3 结果与证据呈现

| 页面区域 | 保留内容 |
| --- | --- |
| 结果横幅和指标 | 风险方向 感染/慢性分数 综合置信度 |
| 依据与建议 | 结构化问诊 主要依据 鉴别建议 检查与复核意见 |
| 模型与路由 | 本地或LLM模式 分支原因 自反馈轮次 |
| RAG证据标签 | 召回摘要 来源标签及相关评分 |
| Agent轨迹标签 | 每个节点的中间证据与执行说明 |
| 专病复核标签 | 专病分数 来源与说明 区分模型和规则 |
| 结构化数据标签 | 与原页面对应的JSON展示字段 |

综合置信度由当前证据与规则共同形成，不能当作已校准的临床概率。轨迹展示的是程序执行记录，不是对模型内部全部推理过程的解释。报告中的“建议检查”属于原型输出，仍需医生结合真实情境判断。

## 5.4 兼容与维护

当前仓库分离backend、frontend、models、examples、scripts、tests与docs。原Streamlit入口保留。Ruff、Prettier和TypeScript构建统一格式和基础检查；工具输出写入被忽略的artifacts，保存的历史证据放docs/evidence，避免日常测试覆盖已有记录。

# 7 项目创新点

## 7.1 技术创新点

本节将创新定位为面向项目场景的技术组合与工程设计，不把第三方网络、工作流框架或API本身声明为原创，也不宣称已证明算法优越性。

### 技术创新一 按证据触发的分层复核

沿用原稿“基础影像初筛加专病方向复核”的设计：主CNN提供基础分布，路由综合症状与知识信号，再决定进入感染、慢性或联合复核。低风险路径可直接综合判断，异常和边界输入有进一步复核入口。当前既支持可选专病模型，也保留规则回退，并在结果中标明来源。

这一设计的贡献是分工和分支组织，不能把专病规则回退称为已完成ViT推理，也不能在没有时延和独立评测时宣称必然提速或减少漏诊。

### 技术创新二 多源证据的状态化组织

将问诊文本、影像分数、检索摘要、复核结果和路由原因写入共享状态，使知识证据能够进入复核判断与解释过程。通过LangGraph表达条件边和反馈，操作者可沿轨迹核对证据如何参与流程，便于调试和后续替换模块。

### 技术创新三 一致性保护与有限反馈

综合结论之后继续检查影像、症状和复核方向之间的关系。证据冲突或支持不足时，可降低确定性、补充保守规则并形成进一步检查建议。反馈由程序约束，避免把多次循环直接等同于“更正确”的诊断。

### 技术创新四 可降级的解释整合

可选LLM接收已有证据并返回结构化内容；网络、鉴权或解析失败由本地规则接管。真实接口成功和七类失败路径均有验证记录。这一设计让基础流程不依赖单一外部服务，同时使降级状态可被看到。

# 7 项目创新点

## 7.2 应用创新点

### 应用创新一 从分类页面延伸到筛查任务

原项目关注的不只是胸片标签，还包括问诊补全、风险分层、依据、复核和下一步检查。通过同一页面呈现这些内容，项目把图像模型嵌入“录入—筛查—解释—复核”的使用过程。相较单纯展示softmax分数，更便于操作者核对症状与影像是否一致。

该价值目前体现为原型功能设计与演示闭环，尚未通过真实基层用户研究证明工作效率或诊断收益。

### 应用创新二 结构化输入与证据透明展示

结构化选项降低现场演示的输入负担，自由文本保留补充表达；RAG证据、Agent轨迹、专病来源和JSON结果并列展示，帮助使用者分清证据、模型与规则。输入变更会清除旧结果，避免把上一轮筛查与新问诊混淆。

可解释展示并不保证结论正确，但为人工发现冲突与复核提供了明确入口。项目不把模型分数或流畅文字当作已验证医学证据。

### 应用创新三 面向教学与低依赖演示

本地权重和小型知识索引支持无云密钥的基础演示；同一原型能展示视觉识别、检索、工作流、LLM和回退之间的关系。结合可执行测试和公开格式的技术文档，评审和学习者可从代码到输出逐项检查，而不是只观看预先录制的结果。

## 7.3 与后续落地的关系

原研究报告提出基层筛查、体检和公共卫生应用方向，这些设想予以保留。真正落地仍需医生参与的需求验证、资源授权、患者级外部评测、隐私治理和责任边界设计。本项目不宣称已在医院部署、取得临床认证或形成商业收入。

# 8 总结与展望

## 8.1 当前成果

本项目已将胸片分类、结构化问诊、轻量知识检索、条件复核、证据整合和一致性保护连接成可本地运行的Web流程。当前版本保留原页面布局，规范了前后端与工具目录，并以实际测试记录说明已完成的功能，而不是仅展示概念架构。

## 8.2 扩展多中心数据验证与分层评估

沿用原稿的后续路线，应在取得授权后引入不同设备、人群和拍摄条件的病例，建立患者级训练、验证与测试划分。评测应报告失败样例、类别表现和不确定输出，不只选择有利的总体指标。现有六图实验可用于功能回归，但不能承担这一独立评测任务。

## 8.3 完善模型与知识证据

后续需找回完整训练日志，补齐本地权重与演示影像来源；对默认CNN、替代模型和专病分支分别验证预处理及输出语义。在独立验证集上评估路由阈值和置信度，避免用演示样例反复调参。知识层应增加可核查出处、版本管理和人工审核，再评估更合适的中文检索方法。

## 8.4 强化交互与运行治理

可在不破坏当前操作流程的前提下增加实时节点状态、稳定的结构化输出校验和经过验证的流式说明。若进入真实使用，还需补齐用户身份、访问控制、审计、临时文件治理、医生反馈及随访机制。后续是否扩展肺结节、积液等识别类型，应由数据与任务验证支持，不仅是增加页面标签。

## 8.5 结语

项目的当前成果是面向肺部异常辅助筛查的可检查工程原型。分层复核、多源证据和保守回退构成技术主线；可运行、可追踪和可复核构成现阶段的交付重点。准确率提升、临床安全收益及规模化应用仍是需要进一步验证的目标。
